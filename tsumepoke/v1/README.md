# 詰めポケ Ver1

2026-10-12 作成。ポケモンのシングルバトルを簡略化したモデルの上で、「初手が唯一の、N ターン確定勝ちの問題」を自動で作り、CLI で出題するプログラムになっている。
今後、条件や手法を変えた版を作ることを前提にしているので、この版で決めたことはここにまとめて書いておく。

## 使い方

`詰めポケ/` のフォルダで実行する。

| コマンド | 内容 |
|---|---|
| `node tsumepoke/v1/generate.js 5 1` | 5ターンまでの問題を乱数の種1で作り、`puzzles.json` に足す（約7分半） |
| `node tsumepoke/v1/play.js` | いちばん長い問題から1問を選んで出題する |
| `node tsumepoke/v1/play.js 608` | id 608 の問題を出題する |
| `node tsumepoke/v1/play.js 608 --answer` | 解答の手順と、正解以外の初手への相手の受けを表示する |
| `node tsumepoke/v1/play.js --list` | 問題の一覧を表示する |
| `node tsumepoke/v1/verify_damage.js 20000 777` | ダメージ計算を PS 本体と比べる |
| `node tsumepoke/v1/verify_turn.js 2000 7` | 1ターンの処理を PS 本体と比べる |
| `node tsumepoke/v1/data.js` | 使える技とポケモンの数、除いた技の理由の内訳を表示する |

## ファイル

| ファイル | 役割 |
|---|---|
| `data.js` | PS から図鑑・技・タイプ相性のデータを読み、Ver1 で使える技とポケモンの候補を作る |
| `engine.js` | 自作の対戦エンジン（ダメージ計算、1ターンの処理、倒れたときの交代） |
| `solver.js` | 確定勝ちの判定、最短ターン数、初手の唯一性、相手の最長の受け |
| `generate.js` | ランダム生成と延長法で問題を作る |
| `play.js` | 出題用の CLI |
| `verify_damage.js`, `verify_turn.js` | PS 本体との一致を確かめるスクリプト |
| `puzzles.json` | 作った問題（`generate.js` の出力） |

## Ver1 のルール

ユーザーと決めたこと（2026-10-12）：
- 対象は確定勝ち。急所と技を外すことは考えない。
- ダメージ乱数は、回答者（p1）の技は最低乱数（85）、相手（p2）の技は最高乱数（100）に固定する。
- 余詰めは「初手だけ唯一解」。2ターン目以降は正解が複数あってもよい。
- PS を参考にした簡略モデルを自作する。命中・急所・特性・持ち物は考えない。
- 生成は、1ターン伸ばす延長法を使う。
- 面白さの評価は Ver1 では入れない。
- 出題は面談議事録の形式（回答者が行動を選ぶと、相手は回答者に最も不利な行動を選ぶ。勝つまで続け、失敗したら最初から）。

Claude が決めたこと（後の版で見直す候補）：
- **能力値**：全員レベル50、個体値31、努力値0、性格補正なし（`data.js` の先頭で変えられる）。
- **素早さが同じとき**：p2 が先に動く（p1 に不利な側に倒した）。
- **追加効果**：確率で起こる追加効果（例：10まんボルトの10%のまひ）は「起こらない」とみなした。急所や外れと同じ扱いにあたる。確率100%で起こる効果を持つ技（例：インファイト、とんぼがえり、確実に能力が下がる技）は、Ver1 で表現できないので候補から除いた。
- **使える技**：変化技、威力が変わる技（はたきおとす等）、反動・吸収の技、連続技、溜め技、必中急所の技などを除き、192個が残った。除いた理由の内訳は `node tsumepoke/v1/data.js` で見られる。
- **使えるポケモンと技の組み合わせ**：PS のランダムバトル（第9世代）の型に入っている技から、Ver1 で使える技が2つ以上あるポケモン335匹を候補にした。問題を作るときは、その中から最大4つの技を選んでいる。
- **手の順番の扱い**：p1 が先に手を決め、p2 はそれを見て選べるものとして探索した（確定勝ちの判定ではこれで結果が変わらない）。p2 は倒れたあとの交代先も、p1 に最も不利なものを選べる。
- **余詰めの数え方**：最短ターン数 N で勝てる初手が2つ以上あれば不採用にした。ほかの初手で N より長くかかって勝てる場合（迂回）は、問題として認めている。数は `puzzles.json` の `detourMoves` に入れてある。
- **出題時の判定**：決められたターン数以内に勝てなくなった時点で失敗にした。遅れて勝てる手を選んでも失敗になる。
- **延長法の中身**：1ターン前の局面を厳密に逆算するのではなく、「相手の場のポケモンの HP を増やす」「倒れる前の相手のポケモンを場に戻す」「交代する前の状態に戻す」「回答者の HP を増やす」などの変更を1〜2回加え、ちょうど N+1 ターンの問題になるかをソルバで確かめる方式にした（石井 2020、tanuki-tsume-shogi の延長法と同じ考え方）。
- **チームの大きさ**：各側最大3匹。問題の最初の局面には、倒れたポケモンは含めない。

## 動かして確かめたこと（2026-10-12）

- ダメージ計算：ランダムな 20,000 通り（攻撃側・防御側・技・乱数 85/100）で、PS の `getDamage` と1件も違わなかった（タイプで無効になる 920 通りを含む）。
- 能力値とタイプ：候補の335匹すべてで、PS が計算した HP・能力値・タイプと一致した。
- 1ターンの処理：ランダムな 1,974 局面で、PS を1ターン動かした結果（全員の HP、場のポケモン、勝敗）と一致した。PS 側は乱数の関数を差し替えて Ver1 と同じ条件にしてある。比べ方が甘くないかを確かめるため、PS 側の乱数を 85 から 86 に変えてみたところ、326 件の不一致が出た。
- 優先度と素早さがどちらも同じ場合（26 局面）は、PS では順番が乱数で決まるので比べていない。
- 生成：`generate.js 5 1` で、1ターン 224 問、2ターン 384 問、3ターン 355 問、4ターン 280 問、5ターン 173 問ができた（約7分半）。
- 出題：id 608 の問題で、間違えたら最初に戻り、正しい手順で「正解です！」まで進むことを、入力をパイプで流して確かめた。

## まだ確かめていないこと・気になっていること

- 問題の質は見ていない。目で見た数問には「相手が交代でかわすので、交代先にも通る技を選ぶ」という読み合いの問題が含まれていた。一方で、同じ技を5回押すだけの問題も多いと考えられる。
- 延長法で作った問題は、元の問題と詰み筋が同じになりやすい（tanuki-tsume-shogi でも同じ傾向が報告されている）。多様性を測る仕組みはまだない。
- 1ターンの探索は PS と一致したが、交代先を選ぶ場面を含む複数ターンの流れは、PS と突き合わせていない。

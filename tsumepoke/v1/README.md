# 詰めポケ Ver1

2026-10-12 作成。ポケモンのシングルバトルを簡略化したモデルの上で、「初手が唯一の、N ターン確定勝ちの問題」を自動で作り、CLI で出題するプログラムになっている。
今後、条件や手法を変えた版を作ることを前提にしているので、この版で決めたことはここにまとめて書いておく。

## 使い方

`詰めポケ/` のフォルダで実行する。

| コマンド | 内容 |
|---|---|
| `node tsumepoke/v1/generate.js 5 1` | 5ターンまでの問題を乱数の種1で作り、`puzzles.json` に足す。段が1つ終わるたびに書き出し、途中経過を1行で表示する |
| `node tsumepoke/v1/generate.js 10 1 --from 7` | ランダム生成をせず、今ある7ターンの問題から10ターンまで延長する |
| `node tsumepoke/v1/play.js` | いちばん長い問題から1問を選んで出題する |
| `node tsumepoke/v1/play.js 608` | id 608 の問題を出題する |
| `node tsumepoke/v1/play.js 608 --answer` | 解答の手順と、正解以外の初手への相手の受けを表示する |
| `node tsumepoke/v1/play.js --list` | 問題の一覧を表示する |
| `node tsumepoke/v1/rate.js 1` | ターン数ごとに10問を乱数の種1で選び、シャッフルした順に出題して、面白さ・難しさ・意外性を5段階で記録する。1問終わるごとに `ratings_1.json` と `ratings_1.csv` に保存する。途中でやめても、次は続きから出す |
| `node tsumepoke/v1/rate.js 1 --csv` | 出題はせず、`ratings_1.json` から `ratings_1.csv` を作り直す（CSV を消したときなどに使う） |
| `node tsumepoke/v1/verify_damage.js 20000 777` | ダメージ計算を PS 本体と比べる |
| `node tsumepoke/v1/verify_turn.js 2000 7` | 1ターンの処理を PS 本体と比べる |
| `node tsumepoke/v1/build_names_ja.js <CSVのフォルダ>` | PokeAPI の CSV から日本語名の表 `names_ja.json` を作り直す（CSV の入手先はスクリプトの先頭に書いた） |
| `node tsumepoke/v1/data.js` | 使える技とポケモンの数、除いた技の理由の内訳を表示する |

## ファイル

| ファイル | 役割 |
|---|---|
| `data.js` | PS から図鑑・技・タイプ相性のデータを読み、Ver1 で使える技とポケモンの候補を作る |
| `engine.js` | 自作の対戦エンジン（ダメージ計算、1ターンの処理、倒れたときの交代） |
| `solver.js` | 確定勝ちの判定、最短ターン数、初手の唯一性、相手の最長の受け |
| `generate.js` | ランダム生成と延長法で問題を作る |
| `play.js` | 出題用の CLI |
| `rate.js`, `ratings_<種>.json`, `ratings_<種>.csv` | 問題を解いて評価する CLI と、その記録。選んだ問題の局面も記録に写すので、`puzzles.json` を作り直しても評価は残る。延長法の同じ系列（元をたどると同じランダム生成の問題になるもの）からは1問しか選ばない |
| `verify_damage.js`, `verify_turn.js` | PS 本体との一致を確かめるスクリプト |
| `puzzles.json` | 作った問題（`generate.js` の出力） |
| `build_names_ja.js`, `names_ja.json` | 出題画面で使う日本語名の表と、それを作るスクリプト。表に載っていない名前は英語名で表示する |
| `introduction.md` | このプログラムを研究の文書として解説したもの（先行研究、手法、生成の時間、今後の展開） |

## Ver1 のルール

ユーザーと決めたこと（2026-10-12）：
- 対象は確定勝ち。急所と技を外すことは考えない。
- ダメージ乱数は、回答者（p1）の技は最低乱数（85）、相手（p2）の技は最高乱数（100）に固定する。
- 余詰めは「初手だけ唯一解」。2ターン目以降は正解が複数あってもよい。
- PS を参考にした簡略モデルを自作する。命中・急所・特性・持ち物は考えない。
- 生成は、1ターン伸ばす延長法を使う。
- 面白さの評価は Ver1 では入れない。
- 出題は面談議事録の形式（回答者が行動を選ぶと、相手は回答者に最も不利な行動を選ぶ。勝つまで続け、失敗したら最初から）。

Claude が決めたこと（後の版で見直す候補）：
- **能力値**：全員レベル50、個体値31、努力値0、性格補正なし（`data.js` の先頭で変えられる）。
- **素早さが同じとき**：p2 が先に動く（p1 に不利な側に倒した）。
- **追加効果**：確率で起こる追加効果（例：10まんボルトの10%のまひ）は「起こらない」とみなした。急所や外れと同じ扱いにあたる。確率100%で起こる効果を持つ技（例：インファイト、とんぼがえり、確実に能力が下がる技）は、Ver1 で表現できないので候補から除いた。
- **使える技**：PS の第9世代の技全体から、変化技、威力が変わる技（はたきおとす等）、反動・吸収の技、連続技、溜め技、必中急所の技などを除くと、192個が残った。除いた理由の内訳は `node tsumepoke/v1/data.js` で見られる。この192個のうち、下のポケモンの技の候補に実際に入っていて、問題に出てくることがあるのは108個になっている。
- **使えるポケモンと技の組み合わせ**：PS のランダムバトル（第9世代）の型には509種が載っている。そのうち、型の技の中に使える技が2つ以上あるポケモン335匹を候補にした。問題を作るときは、その技の候補から最大4つを選んでいる。
- **手の順番の扱い**：p1 が先に手を決め、p2 はそれを見て選べるものとして探索した（確定勝ちの判定ではこれで結果が変わらない）。p2 は倒れたあとの交代先も、p1 に最も不利なものを選べる。
- **余詰めの数え方**：最短ターン数 N で勝てる初手が2つ以上あれば不採用にした。ほかの初手で N より長くかかって勝てる場合（迂回）は、問題として認めている。数は `puzzles.json` の `detourMoves` に入れてある。数えるのは、ソルバの上限（その段で作りたいターン数＋1、ランダム生成では3）以内に勝てる手だけになる。2026-10-23 より前は上限をすべての段で「最大ターン数＋1」にしていたので、それより前に作った問題では、長い迂回まで数えていることがある。
- **延長の元の使い回し**：一度延長の元になった問題（`origin.from` に出てくる問題）は、次の実行でも元にしない。2026-10-23 より前は1回の実行の中でしか守っておらず、`puzzles.json` を残したまま実行し直すと、同じ元から2問目を作っていた。
- **出題時の判定**：決められたターン数以内に勝てなくなった時点で失敗にした。遅れて勝てる手を選んでも失敗になる。
- **延長法の中身**：1ターン前の局面を厳密に逆算するのではなく、「相手の場のポケモンの HP を増やす」「倒れる前の相手のポケモンを場に戻す」「交代する前の状態に戻す」「回答者の HP を増やす」などの変更をランダムに加え、ちょうど N+1 ターンの問題になるかをソルバで確かめる方式にした。変更は1回で、半分の確率でもう1回重ねる。1つの元の問題につき最大60回試し、1問できた時点でその元の問題からの延長は打ち切る。60回と「半分の確率」は目安で決めた値で、資料に根拠はない。
- **延長法の位置づけ**：実際の手を戻すわけではないので、石井（2020）の逆順生成や tanuki-tsume-shogi の延長法（どちらも実際の手を1手ずつ戻す）とは別物になっている。既存の問題を少し変えて検証する点で、tanuki-tsume-shogi の変異法に近い。「延長法」という名前は、1ターン長い問題を作るという目的から付けている。
- **チームの大きさ**：各側最大3匹。問題の最初の局面には、倒れたポケモンは含めない。

## 動かして確かめたこと（2026-10-12）

- ダメージ計算：ランダムな 20,000 通り（攻撃側・防御側・技・乱数 85/100）で、PS の `getDamage` と1件も違わなかった（タイプで無効になる 920 通りを含む）。
- 能力値とタイプ：候補の335匹すべてで、PS が計算した HP・能力値・タイプと一致した。
- 1ターンの処理：ランダムな 1,974 局面で、PS を1ターン動かした結果（全員の HP、場のポケモン、勝敗）と一致した。PS 側は乱数の関数を差し替えて Ver1 と同じ条件にしてある。比べ方が甘くないかを確かめるため、PS 側の乱数を 85 から 86 に変えてみたところ、326 件の不一致が出た。
- 優先度と素早さがどちらも同じ場合（26 局面）は、PS では順番が乱数で決まるので比べていない。
- 生成：`generate.js 5 1` で、1ターン 224 問、2ターン 384 問、3ターン 355 問、4ターン 280 問、5ターン 173 問ができた（約7分半）。
- 日本語名：PokeAPI の CSV（かな表記）から、候補の335匹・192技・タイプすべての日本語名が取れた（2026-10-12）。パルデアのケンタロス3種ときずなへんげのゲッコウガは、PokeAPI の名前では区別できないため手で名前を付けた。抜き出して見た約70件は正しかったが、全件は目で確かめていない。
- 出題：id 608 の問題で、間違えたら最初に戻り、正しい手順で「正解です！」まで進むことを、入力をパイプで流して確かめた。

## 動かして確かめたこと（2026-10-13〜14）

計測は使い捨てのスクリプトで行い、そのスクリプトはこのフォルダには入れていない。

- 生成の時間の内訳：`generate.js 5 1` の総時間 453.0 秒のうち、452.7 秒（99.9%）は問題として成り立つかの検証（`check()`、つまりソルバ）だった。局面や変更を作る処理は合わせて 0.3 秒ほどしかかかっていない。
- 延長の操作ごとの成功率：1回の操作で、ちょうど N+1 ターンかつ初手が唯一になった割合を数えた（元の問題をターン数ごとに60問、各10回）。相手のポケモンを1匹戻す 23.0%、相手の HP を回答者の技1発ぶん増やす 19.6%（`generate.js` にはない操作）、相手の HP をランダムに増やす 10.6%、回答者の交代を戻す 11.1%、相手の交代を戻す 3.3%、回答者の HP を増やす 0.8% だった。
- 延長の試行回数：上限を60回から240回に広げると、元の問題のうち延長できたものの割合は、4 → 5 ターンで 63% から 78% に、3 → 4 ターンで 83% から 88% に上がった（各40問）。成功するときは6〜17回目（中央値）までに成功することが多い。
- 2ターン目以降の一意性：id 1277（5ターン）では、相手が最長の受けをした流れの上では毎ターン勝てる手が1つだけだった。相手のすべての受けまで広げると、回答者が手を選ぶ局面 289 個のうち 104 個で、最短で勝てる手が2つ以上あった。Ver1 の定義（初手だけ唯一解）には合っている。
- 単純化を弱めたときの判定時間：5ターンの問題1問の判定は、Ver1 の平均 57 ms に対し、ダメージ乱数16通りを分岐にすると平均 28.5 秒（約500倍）かかった。急所まで分岐にすると平均40秒を超え、打ち切りも出た。

## まだ確かめていないこと・気になっていること

- 問題の質は見ていない。目で見た数問には「相手が交代でかわすので、交代先にも通る技を選ぶ」という読み合いの問題が含まれていた。一方で、同じ技を5回押すだけの問題も多いと考えられる。
- 延長法で作った問題は、元の問題と詰み筋が同じになりやすい（tanuki-tsume-shogi の変異法でも同じ傾向が報告されている）。重複の判定は局面だけで行っていて、正解の手順が同じ問題は区別していない。多様性を測る仕組みはまだない。
- 延長の5種類の変更の選ばれやすさ（相手の HP を増やす変更だけ他の2倍）と、試行回数の上限（60回）は、成功率を測る前に決めたままになっている。
- 1ターンの探索は PS と一致したが、交代先を選ぶ場面を含む複数ターンの流れは、PS と突き合わせていない。

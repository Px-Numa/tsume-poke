# 詰めポケ Ver1.1

2026-11-13 作成。Ver1（`tsumepoke/v1/`）のルールはそのままにして、生成の記録と設定を増やした版になっている。対戦のルール、ソルバ、生成の手順は Ver1 と同じなので、決めたことは `tsumepoke/v1/README.md` を見る。
初期設定で動かすと Ver1 と同じ問題ができることを確かめてある（下の「動かして確かめたこと」）。Ver1 の問題や評価と比べられることを、この版の条件にしている。

## Ver1 から変えたこと

| 変更 | 初期設定で問題は変わるか |
|---|---|
| 問題ごとに、解答の手順（`line`）、代理指標（`metrics`）、延長の系列の始まりの問題の id（`root`）を `puzzles.json` に書く | 変わらない |
| 延長を試す回数の上限を `--attempts` で変えられるようにした（初期値は Ver1 と同じ 60） | 変わらない |
| 延長の変更に「相手の HP を回答者の技1発ぶん増やす」を足し、`--hit-weight` で重みを決められるようにした（初期値は 0 で使わない） | 変わらない |
| 解答の手順が同じ問題を除く `--dedup-line` を足した（初期値では除かない） | 変わらない |
| `play.js --answer` の解答の手順を、`metrics.js` と同じ選び方にした。`--answer` と `--list` で代理指標も表示する | 出題は変わらない |
| `generate.js` に `--out` を足し、書き出すファイルを変えられるようにした | 変わらない |

`origin.options` には、その問題を作ったときの設定（`attempts`、`hitWeight`、`dedupLine`）が残る。

## 使い方

`詰めポケ/` のフォルダで実行する。

| コマンド | 内容 |
|---|---|
| `node tsumepoke/v1_1/generate.js 5 1` | 5ターンまでの問題を乱数の種1で作り、`tsumepoke/v1_1/puzzles.json` に足す（Ver1 と同じ問題になる） |
| `node tsumepoke/v1_1/generate.js 5 1 --hit-weight 2 --out x.json` | 技1発ぶんの変更を重み2で混ぜて作り、`x.json` に書く。ほかの5種類の変更の重みは合わせて6なので、8回に2回の割合で選ばれる |
| `node tsumepoke/v1_1/generate.js 5 1 --attempts 240` | 1つの元の問題につき延長を240回まで試す |
| `node tsumepoke/v1_1/play.js --list` | 問題の一覧を、非短絡手の数と手の変化つきで表示する |
| `node tsumepoke/v1_1/play.js 1277 --answer` | 解答の手順と代理指標を表示する |

`rate.js`、`verify_damage.js`、`verify_turn.js`、`build_names_ja.js` は Ver1 と同じ使い方になる。

## 代理指標の定義（`metrics.js`）

2026-10-27 のゼミ発表で使った2つの指標を、コードにしたものになっている。

- 解答の手順：毎ターン、残りターン数以内に勝てる手のうち、相手の場のポケモンに一番大きいダメージを与える技を選ぶ。勝てる技がないときは、勝てる交代を選ぶ。相手は最長の受けを選ぶ。
- 非短絡手の数：解答の手順の中で、ダメージが一番大きい技（同じダメージの技が複数あればそのすべて）では残りターン数以内に勝てなくなるターンの数。
- 手の変化：解答の手順で、前のターンと違う手（技の種類、交代先、使うポケモン）を選んだ回数。

発表の数値を出したときのスクリプトは残っていなかった。そのため、`ratings_1` の50問で発表の数値が出るかを確かめて定義を決めた。解答の手順を「勝てる手のうち最初に見つかった手」（Ver1 の `play.js --answer` の選び方）にすると、手の変化の相関は 0.46 になり、発表の 0.54 とは合わなかった。

## 動かして確かめたこと（2026-11-13）

- Ver1 との一致：`generate.js 5 1` で 1,416 問ができ、局面、正解、迂回の数、延長の元が Ver1 の `puzzles.json` とすべて一致した（約4分42秒）。この結果を `tsumepoke/v1_1/puzzles.json` として置いてある。
- 代理指標：`ratings_1` の50問で、発表の数値がすべて再現できた。非短絡手は「0回の27問がすべて面白さ1〜2、2回以上の10問がすべて3以上、同じターン数どうしの相関の平均 0.71」、手の変化は「0回の27問のうち25問が1〜2、相関の平均 0.54」になった。両方が1回以上の17問がすべて3以上になる点も一致した。
- 解答の手順の重複：Ver1 の1,416問のうち、解答の手順（両者のポケモンと手）が同じで同じターン数の組は1組（1ターンの問題2問）しかなかった。回答者の手だけで比べると177問が重複になるが、多くは「じしんを1回打つ」のような1ターンの問題だった。README（Ver1）で気にしていた「延長の元と詰み筋が同じ」は、ターン数の違う同じ系列の問題どうしの話なので、重複の判定ではなく `root` で見分ける。
- `play.js --list` と `play.js 1277 --answer` で、代理指標が表示されることを確かめた。
- `--from`：上の1,416問に `generate.js 6 1 --from 5 --attempts 3` で6ターンの問題を25問足し、25問すべてで `root` が系列をたどった始まりの問題と一致し、`metrics` と `line` が入っていることを確かめた。
- 技1発ぶんの変更：`generate.js 5 1 --hit-weight 2 --dedup-line` で作った問題を、初期設定の1,416問と比べた。成功率が上がると見込んでいたが、結果は逆だった。

| | 初期設定 | 重み2 |
|---|---|---|
| 5ターンの問題の数 | 173 問 | 137 問 |
| 全体の時間 | 4分42秒 | 5分20秒 |
| 5ターンで非短絡手が0回の割合 | 34% | 39% |
| 5ターンで非短絡手と手の変化が両方1回以上の割合 | 57% | 51% |

  1〜3ターンの割合はほぼ同じだった。乱数の種1つだけの比較なので、代理指標の数ポイントの差は偶然の範囲かもしれない。問題の数が減った理由は、この変更が HP の最大値を超えて使えない試行（2026-10-13 の測定で39%）も試行回数に数えているためと考えているが、確かめていない。いまのところ、この変更を初期設定に入れる理由は見つかっていない。

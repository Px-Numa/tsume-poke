# 詰めポケ 被験者実験用 GUI（モックアップ）

2026-11-08 作成。詰めポケ Ver1 の問題をブラウザで解いてもらい、面白さ・難しさ・意外性の評価を集めるための画面ということになる。
計画とまだ決めていないことは `tsumepoke/v1/GUI_PLAN.md` にまとめてある。

## 動かし方

`詰めポケ/` のフォルダで次を実行してから、表示された `http://localhost:8787/` をブラウザで開く。

```
node tsumepoke/gui/server.js
```

npm のパッケージは使っていない。サーバは同じ PC からの接続だけを受け付ける。

| URL | 内容 |
| --- | --- |
| `http://localhost:8787/` | 受付の画面。被験者 ID と問題セットを選んで始める |
| `http://localhost:8787/#free=1277` | id 1277 を記録なしで解く |
| `http://localhost:8787/#free=7&play=3,1` | id 7 でボタンの並びの3番目、1番目の順に手を選んで進める |
| `http://localhost:8787/#free=1277&open=damage` | ダメージ表を開いた状態で始める（`typechart`、`rules`、`settings` も使える） |
| `http://localhost:8787/#free=7&target=2&hover=[data-switch]` | 技のダメージの相手を相手の2番目のポケモンにして、交代のボタンにマウスを乗せた状態で開く（表示の確認用） |
| `http://localhost:8787/#demo` | プレイデモ（チュートリアル）を始める |

## 実験の流れ

受付 → 事前アンケート → ルールの説明 → プレイデモ → 練習問題 → 本番（問題を解く → 評価）の繰り返し → 終了の順に進む。
事前アンケートからプレイデモまでと練習問題は、設定でそれぞれ外すことができる。
プレイデモは被験者が自分でボタンを押して進めるチュートリアルになっている。操作してほしい所は黄色い枠で囲み、枠を点滅させて目立たせる（設定の「プレイデモで操作してほしい所の黄色い枠を点滅させる」で止められる）。マウスを乗せたときの説明や吹き出しが枠の上に重なっても、枠の場所がぼんやり光って透けて見える（設定の「プレイデモの黄色い枠をほかの物より手前に重ね…」で切れる）。黄色い枠で囲んだ所を操作すると先へ進み、ほかのボタンや控えは押しても何も起きない（上のメニューだけはいつでも押せる）。設定の「プレイデモを被験者が自分でボタンを押して進めるチュートリアルにする」を OFF にすると、正解の手順を自動で進めて見せる形に戻る。
プレイデモの最後には「もう一度見る」と「終わる」のボタンが出て、何度でも見直せる（設定の「プレイデモの最後に「もう一度見る」ボタンを出す」で消せる）。
問題の画面では、右上のメニューの「操作確認」でいつでも短い操作説明を見ることができる。今の画面のまま、残りのターン数、場、相手の欄、技と交代の欄、あなたの控え、バトルログの順に枠で囲んで説明を出す。「次へ」を押すまで同じ説明を出したままにする（設定で、決めた時間で自動で進めることもできる）。被験者に操作してもらう手順はなく、「閉じる」で途中でやめられる。プレイデモの最中はこのボタンを出さない。
同じ被験者 ID で受付からやり直せば、終わったところの次から再開する。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `server.js` | サーバ。API と画面のファイルを配る |
| `adapters/v1.js` | 詰めポケ Ver1 のエンジンとソルバをつなぐ部分。画面はここが返す形だけを見て表示する |
| `settings_schema.js` | 設定項目の一覧。設定画面はここから自動で作る |
| `sets.js`, `make_set.js` | 問題セットの読み込みと被験者への割り当て、問題セットを作るスクリプト |
| `sets/*.json` | 問題セット。今は `ratings1`（自分で評価した50問）、`sample10`（被験者ごとに各ターン数10問）、`short`（動作確認用の4問）がある |
| `config/rating_items.json` | 評価の項目と5段階の目安の文言 |
| `config/survey_items.json` | 事前アンケートの項目 |
| `config/settings.json` | 設定画面で保存した値（初期値から変えた項目だけが入る） |
| `public/` | 画面（HTML、CSS、JavaScript） |
| `public/sprites/` | ポケモンの画像を置く場所（任意。`git` には入れない） |
| `results/<被験者 ID>.json` | 被験者ごとの記録（`git` には入れない） |

問題セットは次のように作る。

```
node tsumepoke/gui/make_set.js 名前 --ids 9,188,7          # 決めた問題を全員に出す
node tsumepoke/gui/make_set.js 名前 --sample 10             # 被験者ごとにターン数ごとに10問を選ぶ
node tsumepoke/gui/make_set.js 名前 --from-ratings ../v1/ratings_1.json
```

## 記録の中身

`results/<被験者 ID>.json` には、事前アンケートの答え、始めたときの設定の写し、割り当てた問題（局面の写しつき）、1問ごとの結果が入る。
1問ごとの結果は `rate.js` と同じ項目（正解したか、失敗の回数、あきらめたか、秒数、評価、コメント）に次の3つを足したものである。

- 挑戦ごとの、各ターンに選んだ手と相手の手（`attempts`）
- 解答を見たか（`answerViewed`）
- ダメージ表、タイプ相性表、ルールを開いた回数と、控えのクリックなどの操作の時刻（`uiCounts`、`uiLog`）。相手の控えのクリックは `retarget`、自分の控えのクリックは `retargetMe` として残る

CSV に書き出すスクリプトはまだない。

## 新しい要素を足すとき

特性や状態異常などをエンジンに足すときは、次の順に進めれば画面を作り直さずに済む。

1. 新しいエンジン用のアダプタ（`adapters/v2.js` など）を作り、`features` で対応した要素を `true` にする。`node tsumepoke/gui/server.js --engine v2` で切り替えられる。
2. アダプタの `monView` で `status`、`ability`、`item`、`boosts` に値を入れる。画面は `features` が `true` で設定が ON の要素だけを表示する。
3. 新しい出来事（「やけどのダメージ」など）は、アダプタが `text` に表示用の文を入れて返す。画面は出来事の種類を知らなくても文をそのまま表示する。
4. 新しい設定が要るときは `settings_schema.js` に1行足す。`requires` に要素の名前を書いておけば、対応していないエンジンでは灰色になる。

## ポケモンの画像

次を実行すると、問題に出てくるポケモンの画像を Pokemon Showdown の画像サーバから取ってきて `public/sprites/` に保存することができる。

```
node tsumepoke/gui/fetch_sprites.js
```

正面の画像は `public/sprites/<ポケモンの id>.png`、背面の画像は `public/sprites/back/<ポケモンの id>.png` に入る。
id は PS の内部の名前（`garchomp`、`ninetalesalola` など）を使う。すでにある画像は取り直さないので、問題を作り直したあとにもう一度実行すれば足りない分だけを取る。
画像を足したあとはサーバを再起動しなくても、ブラウザを再読み込みすれば表示される。

設定の「ポケモンの画像を出す」が ON のときは、画像があるポケモンを画像で表示する。画像がないポケモンはタイプの色の丸と名前の頭文字になる。
「自分のポケモンは背面の画像にする」が ON なら、自分の側には背面の画像を使う。
控え、交代のボタン、ダメージ表、詳しい説明の小さいアイコンも同じ決まりで、画像を出さないときはタイプの色の丸と頭文字を小さくして出す。
画像の著作権は任天堂などが持っている。研究の非商用の利用にとどめ、`git` には入れない。

## 対戦の演出

手を選んだあとの出来事には、Pokemon Showdown に似た簡単な演出を付ける。どれも設定の「問題の画面：進行」で1つずつ止められる。

- 技が当たると、攻撃した側の画像が前に出て、受けた側の画像が揺れながら点滅する。受けた側の画像の上には減った HP の割合（「-34.3%」など）が出る。
- HP バーは前の値から新しい値まで少しずつ減っていく。
- 倒れたポケモンの画像は下へ沈みながら消え、そのあとは場に出ない。新しく出たポケモンの画像は小さい状態から現れる。

演出の種類は `app.js` の `fxFor` が出来事の `kind` から決める。状態異常のダメージなどの新しい出来事に演出を付けるときは、`fxFor` に1行足して `applyFx` と `style.css` に動きを書けばよい。

## フォント

画面の文字のフォントは設定の「画面の文字のフォント」で選ぶ。初期値は Zen Maru Gothic にしている。
候補は Google Fonts から読み込める日本語のフォント12種と Windows の標準のフォントの13種類で、一覧は `settings_schema.js` の `FONTS` にある。
設定画面で選ぶとすぐ画面に反映されて見本の文も出る。保存しないで閉じた場合は元のフォントに戻る。
インターネットにつながらないときは Windows の標準のフォントで表示する。
候補を足すときは、`FONTS` に名前と Google Fonts の `family=` の値を1行足せばよい。

## 確かめたこと（2026-11-08）

- アダプタの対戦の処理を `play.js` の出題の処理と比べた。ランダムに選んだ 300 局面で、同じ手を選んだときの相手の手と勝ち負けは1件も食い違わなかった（そのうち 168 局面は勝ちで終わった）。
- API だけで、被験者の登録、事前アンケート、間違えてからやり直して正解、あきらめて解答を見る、評価の保存、同じ ID での再開までを通した。記録のファイルには、失敗の回数、挑戦ごとの手、解答を見たか、ダメージ表を開いた回数が入っていた。
- 対応していない設定（状態異常を有効にするなど）を保存しても初期値に戻ることを確かめた。
- ヘッドレスの Chrome で受付、問題の画面（始めたとき、正解したとき、失敗したとき）、ダメージ表、タイプ相性表、設定を撮り、表示が崩れていないかを見た。
- 2026-11-09 にヘッドレスの Chrome を CDP で操作し、プレイデモのチュートリアル（id 7）を最初から最後まで進めた。説明の手順のあいだは控えや技のボタンを押しても何も変わらず、案内した手と違う技を押すと注意が出て進まなかった。控えにマウスを乗せたときの説明も、この操作で表示を確かめた。
- 2026-11-09 に同じ方法で id 1277 の「操作確認」を押し、6つの説明が 2.5 秒ずつ順に出て自動で閉じることを確かめた（このときの初期値は 2.5 秒だった）。画像を切ると小さいアイコン15個がすべて頭文字の丸になることも確かめた。プレイデモの最後で「もう一度見る」を押すと最初から始まった。
- 2026-11-09 に同じ方法で id 7 を解き、0.1 秒ごとに場の画像の状態と HP バーの幅を読んだ。攻撃側が前に出る、受けた側が点滅する、HP バーが少しずつ 0 まで減る、倒れたポケモンが沈んで消える、次のポケモンが現れる、の順に動いた。

## まだ確かめていないこと

- 事前アンケート、ルールの説明、練習問題、評価、休憩、終了の画面は、画面で操作して確かめていない（API とブラウザの JavaScript の構文の確認だけ）。
- 制限時間と確認の表示は動かしていない。チュートリアルを OFF にしたときの自動のプレイデモも最後まで通していない。
- 実際のブラウザで人が操作して通したことはまだない。対戦の演出の速さや見え方も、人の目では確かめていない。

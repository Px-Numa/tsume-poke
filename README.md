# 詰めポケ（Pokemon Showdown を使った詰み判定の試作）

同時手番ゲームであるポケモン対戦において、「この局面に確定勝ちの手があるか」を判定するプログラムの試作である。
修士研究（同時手番ゲームの「詰め」問題の自動生成）の前段階として、Pokemon Showdown（以下 PS）の対戦エンジンを操作する方法を確かめながら書いた。

ここでいう確定勝ちは、指定したターン数以内に、相手がどの手を選んでも、どんな乱数の結果になっても勝てる手が存在する状態を指している。
勝率99%の手があっても、1%の負け筋が残るなら確定勝ちとは扱わない。

## 動かすための準備

Node.js は 22.18.0 以上が必要になる（PS 本体の要件に合わせている）。

PS 本体はこのリポジトリに含めていないので、同じ階層に clone してビルドする。

```bash
git clone https://github.com/smogon/pokemon-showdown.git
cd pokemon-showdown
git checkout b1156ff19204e48089e2384eb2c9c1a8004f57ce
npm install
npm run build
cd ..
```

commit を固定しているのは、ここで使っている `Battle` クラスの直接操作（局面の注入、`toJSON`/`fromJSON` による複製、乱数の差し替え）が、PS の文書化されていない部分にあたるためである。
PS 自身も「文書化されていない API は予告なく変わる」と注意している。

## スクリプト

`practice/` の中に、PS の使い方を確かめながら書いたスクリプトを置いてある。前半は学習用で、後半が判定の本体になる。

| ファイル | 内容 |
|---|---|
| `a_dex.js` | 図鑑データの引き方。種族値、技、タイプ相性、世代ごとの違い |
| `b_teams.js` | チームの3つの形式（Export / JSON / Packed）の変換と、構成の検証 |
| `c_stream.js` | `BattleStream` を使い、自分で手を送って1戦する。交代の強制と、不正な手のエラーの実例つき |
| `d_battle.js` | `Battle` を直接操作する。HP や状態異常を書き換えて、途中の局面を作る |
| `e_clone.js` | `toJSON`/`fromJSON` による局面の複製、速さの計測、乱数の呼び出しの記録 |
| `e2_solver.js` | 確定勝ちの判定本体。乱数の結果の列挙、AND/OR 探索、動作確認のテスト4種 |
| `e3_one_position.js` | 局面を1つだけ調べる実行用スクリプト |

実行はリポジトリの直下から行う。

```bash
node practice/e3_one_position.js      # 1ターン以内の確定勝ちを調べる
node practice/e3_one_position.js 3    # 3ターン以内まで読む
node practice/e2_solver.js            # テスト4種をまとめて動かす
```

`e3_one_position.js` の1節にチームと局面の書き換えをまとめてあるので、別の局面を試すときはそこだけを編集すればよい。

## 判定のしくみ

1ターンは、次の3段の分岐でできていると考えて探索している。

- p1 の手：どれか1つで勝てればよいので OR として扱う
- p2 の手：すべての手に勝つ必要があるので AND として扱う
- 乱数の結果：すべての結果で勝つ必要があるので AND として扱う

乱数は、PS の `PRNG` を差し替えて、何回目の呼び出しで何を返すかを外から指定している。
桁上がりカウンタの要領で選び方を1つずつ進めることで、1ターンの中の分岐を網羅している。
命中や急所のように当たりと外れしか意味を持たない判定は2本の枝にまとめているため、まひ状態の例では1ターンの枝が約4.4兆通りから4,128通りまで減る。

実測の例を挙げると、ギャラドスとガブリアスが向かい合う局面では、3ターン読んで確定勝ちを証明するのに約43秒（ターンの処理64,347回）かかった。
